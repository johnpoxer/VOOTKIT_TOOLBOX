Preparing a document pack is usually a sequence problem. Your source files might include a Word letter, photographed pages and an existing PDF, while the recipient expects one readable file in a particular order.

Start from the recipient's instructions. Some portals want one combined document; others require separate uploads. Do not merge everything before checking the required file type, size limit, page order and whether signatures or editable form fields must be preserved.

## Build a source inventory

Create a simple list of required items and match each one to its source file. Keep the originals in a separate folder. Use clear working names such as `01-cover-letter`, `02-supporting-document` and `03-appendix`.

Open every source once. Check that photographed pages are legible, scans are complete and the Word document is the approved version. A broken source is easier to correct before it becomes page seven of a combined file.

For a fictional application pack, the inventory might contain a one-page letter, two photographed pages and a three-page PDF. You would expect six pages in the final pack, assuming no cover or blank pages are added.

## Convert only what needs converting

Use [Images to PDF](/tools/pdf/jpg-to-pdf/) for supported photographs and scans. Check orientation and order before export. If a photo includes unnecessary desk area, crop a copy first while preserving the full document edges.

[Word to PDF](/tools/pdf/word-to-pdf/) converts DOCX content in the browser, but its conversion does not reproduce every Word layout feature. Check tables, headers, page breaks and font-dependent spacing. If exact layout matters, compare with an export from the authoring application.

Keep an existing good PDF as a PDF. Converting it to images and back can discard selectable text or other useful document structure without improving the pack.

## Correct page-level problems

Use [Rotate PDF](/tools/pdf/rotate-pdf/) when the document orientation needs correcting. Use [Organise PDF Pages](/tools/pdf/reorder-pdf/) for page ordering and [Delete PDF Pages](/tools/pdf/delete-pdf-pages/) for pages that should not be included.

Check the preview carefully. A printed page number and the page's position in the file may differ, especially when a document contains a cover or introductory pages. Record the file positions you intend to change rather than relying only on the printed numbers.

Do not remove a blank-looking page until you know it is unnecessary. It may separate sections or contain faint content that is hard to see in a thumbnail.

## Merge the checked components

Open [Merge PDFs](/tools/pdf/merge-pdf/) and add the prepared PDF files in the intended order. Download the combined result and compare its page count with the inventory.

In the six-page example, inspect pages one, two, four and six to check the component boundaries and final page. Then scroll through the entire pack. This catches duplicates or omissions that a total page count alone would miss.

For a detailed walkthrough, see [merging PDFs safely](/blog/merge-pdf-files-safely/). A successful merge confirms that output was produced; it does not confirm the contents are the right documents.

## Reduce size after the content is settled

If the result exceeds the upload limit, use [PDF Compressor](/tools/pdf/compress-pdf/) and inspect the output at normal reading size and enlarged view. Check fine print, signatures, diagrams and scanned text.

Compression results depend on the source. A PDF made mostly of text may have less room to shrink than a large scan. If the file is still too large, reconsider unnecessary pages or oversized source images rather than repeating the same operation indefinitely.

Read the [PDF file-size guide](/blog/reduce-pdf-file-size/) for the trade-offs. Keep some room below the portal's limit if its stated units are ambiguous, and verify the exact downloaded file size.

## Check text and special document features

Try selecting text or use [PDF Text Extractor](/tools/pdf/pdf-to-text/) as a spot check. A scanned image requires OCR for text recognition, but OCR output still needs proofreading. Do not assume an OCR tool's text output automatically produces a searchable PDF.

Treat certificate-signed documents, interactive forms and documents with specialised accessibility requirements carefully. A transformation may alter those properties even when the pages still look correct. If the recipient requires the original signed file, follow that requirement instead of merging a transformed copy.

## Repeat the sequence only after one pack works

For recurring supported file steps, inspect [Vootkit Workflows](/workflows/) and its available templates. Check the accepted input and output at each step. The manual sequence in this guide does not imply that every conversion is available inside an automated workflow or on every plan.

Test one representative pack before processing a larger batch. Keep a final checklist with document names, page count, order, readability and upload acceptance.

### Why is my Word layout different?

The browser conversion has layout limitations. Compare against the original and use an authoring-application export when exact fidelity is required.

### Should I compress every file repeatedly?

No. Work from the best source and evaluate each output. Repetition does not guarantee additional useful savings.

### When is the pack finished?

When the exact final file opens correctly, contains the required documents and meets the receiving system's requirements.
